# ATSPM integration

The consumer is [`opensourcetransportation/atspm`](https://github.com/opensourcetransportation/atspm).
This generator repository holds its proposed
[`documentation.json`](../integration/atspm/documentation.json),
[caller workflow](../integration/atspm-update-autogenerated-docs.yml), and
[README text](../integration/atspm/README.md). Copy them to a review branch in
the public ATSPM repository; they are not installed merely by changing this
generator.

The map preserves six explicit pages: Config API, Data API, Identity API,
Report API, Event Log Utility, and Watchdog. It documents 16 named bindings
from 13 source section definitions at the pinned public commit
`82bc9983533671a00d92532289c438e54a5f60e5`. The log reference contains
91 messages. The duplicate-ID allowlist remains limited to 201, 202, 203,
1000, 1001, 1002, 1003, and 9001. Ten missing property summaries are reported
as warnings and do not block generation.

ATSPM uses explicit service assignments. New properties of mapped types appear
automatically. A new section needs a deliberate page assignment; the workflow
does not guess which API or service owns it. Definitions outside `sourcePaths`
also require a map update. The documentation describes source annotations and
initializers, not deployed values or every runtime validation rule.

The pinned [baseline check](baseline.md) verifies the existing presentation
against the public source commit. Before adopting the map on a current ATSPM
branch, run `check` against that branch and adjust registrations or page
assignments based on its actual source. The current public `main` has changed
since the pinned commit, so the frozen map is not a claim of current coverage.

The caller template targets a development branch named `Code-Documentations`
for both source and documentation PRs. Change that name if the public ATSPM
review branch differs. It calls the generator's `main` after the shared workflow
is merged there; before then, use a pushed generator feature branch or commit.
The workflow stages output, uploads a preview, and proposes a review PR. A
person reviews and merges it; Pages publication is configured separately.
