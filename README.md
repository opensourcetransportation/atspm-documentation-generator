# ATSPM documentation generator

This shared tool documents C# repositories. It reads source with Roslyn, writes
configuration and log references, creates safe JSON/environment examples, and
validates a MkDocs site. Each consumer keeps a small map and generated files
in its own repository. ATSPM is the bundled default.

The tool documents the **source contract**. It does not run the application,
read deployed values, change deployment settings, merge PRs, or publish a site
without a separately enabled workflow.

## Add a repository

Work on a review branch. A consumer normally adds these files:

```text
GenerateDocuments/documentation.json
.github/workflows/update-documentation.yml
docs/autogenerated/...
```

1. Build this generator with .NET 8: `dotnet build GenerateDocuments.sln
   --configuration Release`. From this checkout, create the consumer map:

   ```powershell
   dotnet src/GenerateDocuments/bin/Release/net8.0/AtspmDocsGenerator.dll init --source-root C:\path\to\consumer --product-name "My Project"
   ```

2. Edit `GenerateDocuments/documentation.json` in the consumer. Point
   `sourcePaths` at its C# folders. Use one `autoDiscover` page for a small
   utility, or explicit pages when services use different settings. Run:

   ```powershell
   dotnet src/GenerateDocuments/bin/Release/net8.0/AtspmDocsGenerator.dll check --source-root C:\path\to\consumer
   ```

3. Copy the [generic caller](integration/update-documentation.yml) to the
   consumer's `.github/workflows/update-documentation.yml`. Set the push,
   `source-branch` and `target-branch` to its review branch. Replace **both**
   SHA placeholders with the same reviewed, pushed generator commit. Push with
   `create-pr: false` and review the `documentation-preview` Actions artifact.
4. After that preview looks right, set `create-pr: true` and allow Actions to
   create PRs. Later source pushes create or update one **draft** documentation
   PR against the chosen branch. Review and merge it yourself. The files and
   configuration snapshot then stay with the source repository.

GitHub shows the manual Run workflow button only when the caller exists on
the default branch. During branch-only development, push to the configured
development branch. No main-branch merge is needed to preview.

## How a run works

```text
Source commit + repository map + prior committed snapshot
  -> discover C# configuration types and log declarations
  -> check mappings and compare configuration
  -> generate docs, templates and change report in staging
  -> strict MkDocs build + downloadable preview artifact
  -> optional draft PR with docs and reviewed map additions
  -> optional Pages preview from committed docs after PR merge
```

A property added to a scanned type appears automatically. A new section joins
an `autoDiscover` page; an explicit page needs a deliberate assignment. Run
`sync --source-root <path> --container <slug>` to preview additive map changes,
then repeat with `--write` to apply them. `sync` never guesses which service
owns a section. The shared workflow can do this when `sync-container` names
one page. Unmapped settings are flagged for review, but this cannot prove a
deployment contains them.

The target branch's previous `configuration-snapshot.json` supplies the
comparison baseline. `configuration-changes.md` reports added, removed and
changed settings, defaults, required annotations, enum options, environment
names and service mappings. Unchanged configuration retains its last report.
Preview artifacts exist even when there is no meaningful difference and no
PR. See [discovery and sync](docs/discovery-and-setup.md), [change
reports](docs/configuration-change-reports.md) and the [shared PR
flow](docs/shared-pr-automation.md).

## The repository-owned map

The [small example](config/documentation.example.json), [automatic-page
example](config/documentation.auto.example.json) and [JSON Schema](config/container-config-map.schema.json)
show the version-2 format. A minimal map is:

```json
{
  "schemaVersion": 2,
  "productName": "My Project",
  "sourcePaths": ["src"],
  "containers": [
    { "name": "My Project", "slug": "my-project", "autoDiscover": true }
  ]
}
```

`sourcePaths` and `logMessages.sourcePaths` are relative to the consumer root.
The map belongs at `GenerateDocuments/documentation.json`. The shared
workflow's `output-directory` defaults to `docs/autogenerated`, which must
contain only generator-owned files. An ownership manifest prevents overwriting
handwritten files. The map can also define explicit `configurationTypes` for
unannotated bound classes, `excludedProperties`, `propertyDescriptions`, safe
example overrides, branding and page assignments. Missing registrations and
misspelled overrides fail validation. See [consumer configuration](docs/consumer-configuration.md),
[setup](docs/discovery-and-setup.md) and [branding/logs](docs/generic-presentation.md).

Logging is optional. A `logMessages` object enables structured `LoggerMessage`
coverage; omit it for configuration-only documentation. Set
`includeOrdinaryCalls: true` to index literal/interpolated ordinary `ILogger`
calls. Those calls have no declared event ID, and computed messages are omitted.
Intentional duplicate structured IDs must be listed explicitly. See the
[Data Migration example](integration/data-migration/documentation.json).

## Outputs and direct action use

The generator writes one Markdown page and two downloadable templates per
configured page, plus `index.md`, `configuration-templates.md`, the snapshot,
change report, optional `log-messages.md`, and an ownership manifest. Template
strings and credential-like fields use safe placeholders. The site navigation,
branding and browser log exports follow the map. [Template details](docs/configuration-templates.md)
explain safe values and source revision.

The reusable workflow is the simplest route to draft PRs. For direct generation,
check out the C# source, set up .NET 8 and Python, and pin the composite action
to a full generator commit SHA:

```yaml
- uses: opensourcetransportation/atspm-documentation-generator@<full-commit-sha>
  with:
    source-root: .
    config-file: GenerateDocuments/documentation.json
    output-root: docs/autogenerated
    repository-url: https://github.com/${{ github.repository }}
    repository-ref: ${{ github.sha }}
```

`source-root` defaults to `.`, `output-root` to `docs/autogenerated`, and
`validate-site` to `true`. Omitting `config-file` uses the bundled ATSPM map;
an explicitly missing file fails. The composite action generates and validates
but does not commit or open a PR. The shared PR workflow owns those steps.

For a local site build after generation, install `requirements.txt`, set
`DOCS_CONFIG` to the consumer map and `DOCS_DIR` to its generated directory,
then run `python -m mkdocs build --strict` from this repository. Source links
use the supplied repository URL and commit. Defaults shown in tables are C#
source initializers, not necessarily `appsettings.json` or runtime values.
The `Required` column follows supported property annotations, not CLI rules.

## Pages previews and publishing

The optional [Pages caller](integration/preview-documentation-pages.yml) builds
a second preview artifact from **committed** generated files after the docs PR
is reviewed and merged. It validates their manifest and source revision and
does not regenerate them. The example sets `publish: false`; no consumer site
is currently published. [Pages setup](docs/pages-publication.md) describes
the separate reviewed change needed to enable a protected deployment. Wiki
publishing is not implemented.

in each consumer. Use review branches and pin a reviewed generator commit before
activating its caller workflow.

## When something fails

| Symptom | Next check |
| --- | --- |
| Unmapped section | Choose its explicit page, or use one automatic page. Preview `sync --container <slug>` before `--write`. |
| Missing type or setting | Check source-root-relative `sourcePaths`, attributes, exact `configurationTypes`, and supporting C# types. NuGet-only types and direct `IConfiguration` reads are not discovered. |
| Missing or duplicate logs | Check log folders and `includeOrdinaryCalls`; review duplicate IDs before allowlisting them. |
| Output directory rejected | Keep it dedicated to generated files; restore a missing/corrupt snapshot or manifest from the reviewed branch. |
| No draft PR | Check `create-pr`, Actions PR permissions and whether the change is meaningful. Timestamp/revision-only changes are intentionally ignored. |
| Pages preview rejected | Commit the map and all generated files together; the Pages workflow validates the checked-out commit. |

The [implementation plan](docs/implementation-plan.md) records scope and the
remaining Data Migration gap. Code lives in `src/GenerateDocuments`, reusable
workflows in `.github/workflows`, and pinned consumer checks in `scripts`.
Run `dotnet test GenerateDocuments.sln --configuration Release` and
`python -m unittest discover -s scripts -p 'test_*.py'` after changes. No
application code is executed by documentation generation.
